# Smart Schedule Coordinator

**「普段の予定」をまとめて入力し、必要な日だけ修正できる日程調整Webアプリです。**

管理者がイベントと回答項目を作成し、参加者が共有リンクから参加可能な日時を回答します。管理者は集まった回答をもとに、候補日時のランキングを確認できます。

[アプリを開く](https://shin-systems26.github.io/schedule-app/)

## 解決したい課題

サークルの練習やグループ活動では、候補日が多いほど回答の入力と集計に手間がかかります。また、先の予定が決まっていない人に、参加可否の二択だけを求めるのは難しい場合があります。

そこで、次の方針で日程調整の仕組みを作りました。

- **入力をまとめる：** 曜日と「午前・午後・夜」の組み合わせで回答し、イベント期間内の日付に反映する。
- **例外だけ直す：** 特定の日に予定がある場合は、その日時だけ修正する。
- **未確定も回答できる：** ○・×・？の3段階で予定を表す。
- **主催者の判断を助ける：** 回答を集計し、候補日時と参加可否の内訳を表示する。

入力時間の短縮率や利用人数などの効果測定は、現時点では掲載していません。

## 使い方

### 管理者

1. 管理者ホームからGoogleアカウントでログインする。
2. イベント名・開始日・終了日を入力する。
3. 「対面」「オンライン」など、日程を分けて回答してほしい条件を1行ずつ入力する。
4. 作成後に参加者用リンクをコピーし、参加者に共有する。
5. 管理者ホームで「回答を更新」し、回答者一覧と候補ランキングを確認する。

受付の締切・再開や、イベントと回答の削除も同じホームから操作できます。削除は取り消せません。

### 参加者

1. 主催者から届いた回答リンクを開く。参加者のログインは不要。
2. 名前を入力し、各条件について曜日・時間帯ごとの予定を選ぶ。
3. 必要に応じて「特定の日だけ細かく修正する」から日時別に変更する。
4. 回答を送信する。

2つ目以降の条件には、最初の条件の回答をコピーできます。

## 主な機能

- Googleログインと、自分のイベント一覧
- イベント名・期間・回答項目の自由設定
- 参加者リンクの表示・コピー
- 曜日別の簡易入力と、9時から22時までの1時間単位の詳細入力
- ○（参加できそう）・×（参加できない）・？（未確定）の回答保存
- 回答者一覧と、条件ごとの候補日時ランキング上位10件
- 受付締切・再開、イベントと回答データの削除
- スマートフォン幅への対応（詳細な日時表は横スクロール）

回答項目の自由設定は、**日程を回答する条件を追加する機能**です。自由記述・選択式など、任意の種類のアンケートを作る機能ではありません。

## 工夫した点

### 1. 大まかな回答から詳細な回答へ進める

毎日の全時間帯を最初から入力するのではなく、まず普段の曜日ごとの予定を設定します。それをイベント期間に展開し、例外だけ変更できるようにしました。未入力の日時は「？」として扱います。

### 2. 管理者の操作を1つのホームにまとめる

ログイン・作成・管理が別々のページに分かれていた構成を、管理者ホームに統合しました。参加者への共有もボタンで行えるため、HTMLファイル名やURLの書き換えを意識せず操作できます。

### 3. 変更前のリンクと回答を引き継ぐ

既存の参加者リンクや管理画面のリンクは、新しい画面へ転送します。また、質問設定と回答データの旧形式も読み取れるようにし、画面構成の変更に伴う影響を抑えています。

### 4. 参加できない人の数も考慮して集計する

各条件・日時について、次の式でスコアを計算します。

```text
スコア = ○の人数 × 3 + ？の人数 × 0.5 − ×の人数 × 4
```

同点の場合は、○が多い順、×が少ない順、日時順に並べます。「全員○」「×なし」などの表示と人数の内訳を併記し、主催者が判断できるようにしています。

これは固定の重みを使った集計であり、AIによる予測や最適日程の保証ではありません。重みの妥当性は今後の利用・検証で見直す余地があります。

- **HTML / CSS / JavaScript：** 画面、入力操作、集計処理
- **Firebase Authentication：** 管理者のGoogleログイン
- **Cloud Firestore：** イベントと回答の保存
- **Firestore Security Rules：** データへのアクセス制御
- **GitHub Pages：** 静的ファイルの公開
- **Git / GitHub：** ソースコードと変更履歴の管理

専用のアプリケーションサーバーを立てず、ブラウザーからFirebaseを利用する構成です。管理者は自分のイベントを取得し、その回答をブラウザー上で集計します。回答の表示は「回答を更新」で再取得する方式です。

## 分割日程調整

全員が同じ時間に集まれない場合に、複数回の開催で回答者全員の参加機会を確保する機能です。通常ランキングと従来の採点は変更していません。

1. イベントは従来どおり作成します。モード選択はありません。管理画面には従来の日程ランキングと、その下に「分割して練習・開催する場合」を併記します。回答があれば初期条件で分割案も自動計算します。
2. 参加者と主催者が、従来どおり参加者用リンクから予定を回答します。
3. 管理画面で回答項目（対面など）と「主催者の回答」を選びます。主催者は対象者数・最低人数から除外します。未指定なら全回答者を対象とし、主催者の参加可否は未確認と表示します。
4. 最大回数（1〜5）、最低人数、所要時間（1時間単位）を設定して「組み合わせを提案」を押します。
5. 必要なら「期間・時間帯と優先条件を調整」を開きます。対象はイベント期間内の最大366日、9〜22時の回答枠です。「21時以降を避ける」は優先条件、終了時刻を21時にする設定は必須条件です。
6. 上位5案について、各回の参加可能者・人数・主催者の可否、全体の確保率、参加機会がない人を確認します。「このプランを選択」で検討中の案を明示できます。

### 計算上の扱い

- ○（`yes`）だけを参加可能として扱います。？・未回答・×を成功扱いしません。
- 2時間なら連続した2枠すべてで○が必要です。複数の回答項目は混ぜず、選んだ項目の中で計算します。
- 同じ人が複数回に参加できても、確保率の分子では一度だけ数えます。各回の人数は「その回に参加可能な人数」で、1回だけに割り当てた人数ではありません。
- 回答ドキュメントIDを参加者の識別に使います。同名でも別回答です。同一人物の重複送信や未回答の人を自動判別する名簿機能はありません。「全員」は主催者を除く登録済みの回答者を指します。
- 時間が重なる開催は組み合わせません。同じ日の連続する別開催は許可します。
- カバー人数を最優先し、標準では開催回数 → 主催者が○でない回数 → 避けたい時間との重なり（時間数）→ 各回の人数差（最大−最小）の順に比較します。時間帯優先・人数差優先にも変更できます。最後は日時順で安定して並べます。
- 主催者参加を必須にすると、主催者が全時間○の候補だけを使用します。必須でなければ、不参加・未確定の回を明示した代替案も残します。
- 完全カバーがなければ、条件内でカバー人数の多い代替案を表示します。最低人数などを勝手に緩めることはありません。

### 探索範囲と制限

実際の回答から開催候補を作り、少ない開催回数から組み合わせを列挙します。BigIntの集合で人数を数え、残り候補でもカバー人数が改善しない枝を省きます。探索完了時は、このモデルと指定条件内で上位案を比較済みです。

組み合わせ爆発に備え、Web Workerで計算し、探索ノード数250,000・実行時間20秒の上限を設けています。ノード上限に達した場合は**暫定案であり、最適性や最大カバー人数は未保証**と表示します。時間上限なら中止し、期間・回数を減らすよう案内します。計算の中止、条件変更、ログアウト、別イベントへの移動でもWorkerを終了し、結果を消去します。

設定・選択したプランは画面内のみで有効で、更新・移動するとリセットされます。Firestoreへのプラン保存、参加者への自動通知、参加確定、30分単位の計算は含みません。

### データと権限

既存回答を読み取って主催者のブラウザー内で計算します。新たな回答読取や外部送信は行いません。新旧回答形式はどちらも使用でき、移行・既存回答の上書き・削除は不要です。

イベントの保存フィールドは従来どおりです。以前保存した `scheduleMode` があっても表示の切り替えには使用せず、すべてのイベントでランキングと分割案を併記します。既存フィールドの削除・移行は行いません。主催者の回答ID・参加者名・設定・計算結果は公開されるイベントドキュメントに保存しません。今回の表示変更に伴うSecurity Rulesの追加フィールド許可は不要です。既存の所有者限定読取は引き続き必要です。

## 保存データと互換性

```text
events/{eventId}
  title, startDate, endDate, ownerId, isOpen, groups, createdAt
  responses/{responseId}
    name, answers, createdAt
```

- `groups` は回答項目のIDと名前の配列です。
- `answers` は項目IDごとに、日時と回答（`yes` / `no` / `maybe`）を保存します。
- 質問設定は `groups`、旧 `questions`、旧固定3項目（`env` / `eng` / `online`）の順に読み取ります。
- 集計は `answers[groupId]` と、旧形式の `response[groupId]` に対応します。
- 削除は受付を閉じてから回答を400件ずつ処理し、最後に親イベントを削除します。途中失敗した場合は、残ったデータの削除を再試行できます。

## アクセス制御と検証範囲

管理者の本人確認にはAuthenticationを使用し、データの読み書きの制御にはSecurity Rulesを使用する設計です。画面上でボタンを隠すことや、JavaScriptで所有者を確認することだけでは、データへのアクセス制御にはなりません。

デプロイ済みのSecurity Rulesはこのリポジトリには含まれていません。運用には、以下のルールが設定されている必要があります。

- 参加者がイベント情報を読み取れること。
- イベント作成時の `ownerId` がログイン中の本人と一致すること。
- 所有者のみが自分のイベントを更新・削除し、その回答を閲覧・削除できること。
- 自分のイベント一覧を取得する `where("ownerId", "==", uid)` のクエリが許可されること。
- 回答作成は存在する受付中イベントに限定され、回答データの形式も検証されること。

実際の参加者名・回答はFirestoreに保存します。リポジトリのテストデータは架空のものです。

### 全員の回答一覧

管理画面の「全員の回答を一覧で確認」を開くと、質問項目・日付ごとに全員の回答を確認できます。回答者を選ぶと個人の予定に絞れます。日付は「前の日」「次の日」でも切り替えられ、表はスマートフォンで横スクロールできます。○・×・？と、保存されていない回答（—）を区別します。同名の回答は番号で区別します。

既存の管理者用読み取り結果のみを使用し、データの変更や新しいFirestoreアクセス・Rules変更は行いません。ログアウトやイベント切替時には表と回答者名を消去します。旧形式の回答にも対応します。

### 100％に届かないときの確認候補

通常は○のみを数えます。指定期間・時間帯・所要時間に○がない人を表示し、100％にできない理由を示します。「？の人に確認できれば全員が参加できる案も探す」をチェックすると、明示的な？を含む確認候補を探せます。×・保存のない回答は含めません。各回の確認対象者と○だけで確保できる人数を併記し、見込み100％を確定100％と区別します。主催者必須の場合は引き続き主催者の○が必要です。保存済み回答は変更しません。

### 曜日別の表と10分刻みの修正

参加者画面は元の○・×・？を直接押す表です。平日は月〜金×朝・1〜5限・放課後の7区分、土日は午前・午後・夜の3区分を表示します。まとめて選択するチェックボックスはありません。

「特定の日だけ細かく修正する」を開くと、日付×10分刻みの表を表示します。8〜22時を左右にスクロールし、マスを押して修正できます。パソコンではドラッグで同じ回答を続けて付けられます。長い期間は7日ずつ切り替えます。質問①の回答コピーと直前操作の取り消しにも対応します。特定日の修正は曜日設定より優先します。

昼休み・授業間の休憩・未選択は？のままです。回答保存と計算は前版と同じ区間形式で、従来の1時間回答も読み取ります。登録済み回答は変更しません。
